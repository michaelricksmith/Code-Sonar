# RICK Memory — 2026-09-02

## Security boundary increment

- Michael Smith approved completion of the remaining product-readiness program,
  with security first, scoring accuracy second, and UI/UX third.
- The first bounded security increment implements mandatory bearer authentication
  for API routes except the independently HMAC-authenticated GitHub webhook.
- Non-loopback operation fails closed without `CODESONAR_API_TOKEN`; tokenless
  use is limited to explicit loopback development mode.
- CORS is an exact environment-configured allowlist with local-only defaults.
- Caller-controlled scan, hotspot, history/drift, and remediation repository
  paths are contained beneath `CODESONAR_SCAN_ROOT` by default. The unsafe legacy
  path mode is an explicit development-only escape hatch.
- Regression tests cover authentication, startup configuration, hostile/configured
  origins, path escape rejection, and preservation of webhook HMAC behavior.

## Scoring authority increment

- Analyzer runs now return explicit completion records. Any analyzer failure
  prevents an authoritative score/grade instead of being treated as no findings.
- Scoring version `1.0` is exposed by scan APIs and persisted in history;
  existing unversioned records load as `legacy-unversioned`.
- Focused regression coverage addresses failure gating, complete scans, version
  round trips, legacy loading, and unchanged-input determinism.
- Added an empty, versioned benchmark scaffold for frozen findings and blinded
  expert labels; no repositories or labels were invented and calibration did
  not change.

## Calibration Evidence v1

- Evidence contracts now separate anonymous repository metadata, frozen scans,
  individual/adjudicated blinded labels, and finding-level reviews.
- Capture strips repository identity, source evidence, file/host paths, and
  secrets; canonical SHA-256 hashes preserve artifact integrity.
- Evaluation includes grade agreement, ordinal Spearman correlation, weighted
  kappa, per-analyzer precision, severity agreement, deterministic bootstrap
  intervals, and stratum views.
- The scorer rejects duplicate IDs and produces canonical contribution evidence
  with category caps/weights. Accurate summation did not change established
  regression outputs, so scoring remains version `1.0`.
- The 12-case manifest is intentionally metadata-only. No repository selection,
  expert label, accuracy claim, weight change, or threshold change was made.
- Fail-closed duplicate detection found an existing dead-code analyzer collision
  for repeated method names. Stable location-aware SHA-256 IDs fixed it; the
  final self-scan and 445-passed/1-skipped backend suite are green.

## Unified UI context increment

- Local scans and managed GitHub projects now feed one active repository and
  deterministic scan baseline across Overview, Findings, Risk Map, History,
  Ask Sonar, and Remediations.
- Selecting a managed project restores its persisted authoritative score and
  findings without copying mock data or exposing its backend checkout path.
- Managed scan and drift actions update the shared workspace immediately.
- Integrations now points to the repository workspace instead of rendering a
  second independent project dashboard.
- Persisted scans without live hotspot aggregation show an explicit rescan
  state instead of incorrectly presenting an empty risk map.

## Remediation authorization increment

- Caller-controlled remediation approval and repository paths were replaced by
  a server-owned signed capability minted from a verified persisted plan.
- The capability expires after five minutes, is single-use, and binds request,
  repository, scan, finding, plan, Git base commit, executor, remediation kind,
  and instruction.
- Prepared workspaces preserve the immutable binding and their worktrees,
  branches, and in-memory identities are cleaned on every workflow exit.
- Legacy direct remediation endpoints are closed. The grounded Ask Sonar
  approve-and-run flow remains the supported frontend contract.
- Manual scan, history, and remediation API responses no longer reveal server
  filesystem repository paths.

## Tenant isolation increment

- Unique bearer tokens may be mapped to tenant IDs with the server-owned
  `CODESONAR_API_TENANT_TOKENS` JSON configuration. The legacy API token is
  bound to `CODESONAR_TENANT_ID` and remains single-tenant compatible.
- Tenant identity is carried in an async-safe server context and persisted on
  project, scan-history, and GitHub-installation records. It is never accepted
  from `X-Code-Sonar-Tenant` or another caller-selected header.
- Projects, history scans, Ask Sonar grounding/remediation plans, and GitHub
  installations return not found or an empty scoped list across tenant
  boundaries. Remediation execution inherits the gated scan lookup.
- HMAC-verified GitHub webhooks derive tenant identity exclusively from the
  stored owner of the payload installation ID. The binding is carried into
  project resolution and background scan jobs; job and audit reads are scoped,
  and unknown installations remain unassigned without mutating tenant state.
- This bounded checkpoint deliberately does not claim encrypted or
  transactional production persistence; that remains the next storage layer.
- Verification: 434 backend tests passed, 1 skipped, 86% coverage; Ruff and
  strict mypy passed.
